# 🧠 How I Think About Engineering

### Solve the problem, not the technology

Technology should serve the problem—not the other way around.

### Design for change

Good systems should be able to evolve as requirements, technology and scale change.

### Make trade-offs explicit

Architecture is often about choosing which compromises are acceptable.

### Prefer evidence over assumptions

Prototype, test, measure and observe whenever practical.

### Keep complexity intentional

Complexity should exist because the problem requires it—not because the implementation allows it.

### Learn continuously

Fifteen years of experience does not mean fifteen years of using the same ideas.

Technology changes. Engineering practices change. The learning never stops.
